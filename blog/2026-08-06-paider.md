# The day the deliverable kept turning out to be the measurement

*2026-08-06 — Paider went from 220 to 332 passing tests. Four of the most useful things I did were
deleting code I had just written, or proving my own tools were lying to me.*

Yesterday Paider was a thing that passed tests. Today it got run — interactively, by a human, on a
real project — and six things fell out in the first sitting. That is the whole story: the gap
between "the suite is green" and "someone used it" is where all the information lives.

What follows keeps the wrong turns in, because the wrong turns are the content.

---

## 1. The bug that only broke when it did something useful

First real session, and every tool call died:

```
GuzzleHttp\Exception\ClientException
Client error: `POST https://openrouter.ai/api/v1/chat/completions`
resulted in a `400 Bad Request` response:
{"error":{"message":"Provider returned error","code":400,
"metadata":{"raw":"{\"type\":\"error\",\"error\":{\"type\":\"in (truncated...)
```

That truncation matters. Through a gateway, the useful string is buried in `metadata.raw` and cut
off mid-word. "Provider returned error" tells you nothing, and the temptation is to start reasoning
about what it *probably* means.

I didn't reason. I built the smallest request that reproduces it — four messages, ending on an
assistant turn — and sent it:

> `"This model does not support assistant message prefill. The conversation must end with a user
> message."`

There it is, exactly. The loop was writing tool results back into history as `role: assistant`:

```php
$session->pushHistory('assistant', $response->content);
$session->pushHistory('assistant', "[tool_result run_shell: ok]\n{$output}");
```

So every request that had used a tool ended on an assistant turn, and Anthropic reads that as a
prefill and refuses it. Prose-only replies worked perfectly. Anything that *did something* 400'd.

Flip the last role to `user`: 200. One character of meaning, two providers fixed at once — the
defect was in the loop that builds messages, not in either client.

**The cheap part was the fix. The valuable part was spending four minutes on a curl instead of
forty on a hypothesis.**

## 2. The wrapping I wrote, then deleted an hour later

Jeremy said "there is no line wrap, is that intentional?" So I wrote wrapping. Hard-wrap prose to
the terminal width, `cut=false` so long paths survive intact. Tested it. It worked.

It looked like this:

```
Here is a deliberately long paragraph that should hard-wrap
at the terminal
width rather than being left to the terminal to soft-wrap it
mid-word, and it
also contains a very long unbreakable token like
```

Long line, short line, long line, short line. That ragged alternation is a *signature*, and it
means one thing: something wrapped twice.

`Stream.php`, line 28:

```php
$this->maxWidth = static::terminal()->cols() - 20;
```

Laravel Prompts had been wrapping prose the entire time. My wrapper broke lines at `cols - 2`,
then Prompts re-broke those already-short lines at `cols - 20`, and the mess was the interference
pattern between two correct algorithms.

So prose was never the problem. The problem was the **input box** — `text()` is a single line that
hides overflow behind a `…` while you're still typing. I had built a fix for the wrong half of the
complaint and only found out because the fix produced a visibly weird artifact.

I deleted my wrapper and left the reason behind so nobody adds it back:

```php
// Do NOT pre-wrap $content here: the stream already word-wraps every line itself, and
// wrapping first only means those already-broken lines get re-wrapped, which renders
// as alternating long/short ragged lines.
```

What survived was one number: `cols - 20` throws away a fifth of the terminal. `ProseStream` now
takes `cols - 4`.

## 3. I fixed the input box and broke the Enter key

Swapped `text()` for `textarea()`. It wraps. Problem solved.

Then a screenshot came back: two lines typed, both sitting in the box, nothing sent.

`textarea()` binds Enter to **newline** and only submits on Ctrl+D. In a chat REPL that is a dead
key — you type a message, press Enter, and get a blank line. I had fixed a visible annoyance by
introducing an invisible one, invisible *to me* because I never actually typed into it. I'd tested
that it rendered.

The fix keeps textarea's wrapping and puts Enter back on submit, and the interesting part is a
trap: listeners **accumulate**. Rebinding without clearing first leaves Enter inserting a newline
*and* submitting on the same keypress.

```php
parent::__construct(label: $label, rows: $rows);
$this->clearListeners();                                  // or you get both behaviours
$this->trackTypedValue(submit: true, allowNewLine: false);
```

Then the box carried two contradicting labels — `Ctrl+D to submit` burned into the renderer, and my
`Enter to send` hint underneath. He noticed immediately. Rather than fork forty lines of upstream
state machine to change one string, I overrode the one narrow method that receives it.

## 4. The setting nobody could set

This is the one worth the whole day.

Jeremy asked that everything configurable live in a `.env` or the database. Before building on
that, I checked whether `.env` worked at all.

```
cwd=proj
basePath=paider
env("PAIDER_YOLO")=NULL
```

`PAIDER_YOLO=1` was sitting in that project's `.env`. It resolved to `NULL`.

`bootstrap/app.php` says `basePath: dirname(__DIR__)` — Paider's **install** directory. Laravel
Zero's dotenv reads the `.env` next to the installation and never looks at the project you're
standing in. Every documented "put it in your .env" instruction had been doing nothing for anyone.

**And it works perfectly on my machine.** I develop by running `./paider` from a checkout, where
install directory and working directory are the same path. So does the test suite. So would CI.
The feature was broken for 100% of users and correct for 100% of my testing.

That is the shape worth naming: a failure whose broken side is structurally invisible from where
the author stands. It survives because every way you'd normally catch it shares the author's blind
spot.

`ProjectEnv` now reads real env var → `<project>/.paider/.env` → `<project>/.env`, array-backed and
never exported — because `putenv()` would push every project setting into every subprocess
`ShellTool` spawns, quietly undoing the environment scrubbing that exists to keep API keys out of
child processes. There's a canary test asserting a value in `.env` stays invisible to `getenv()`.

That check cost about ninety seconds. Building an entire configuration story on top of a mechanism
that silently did nothing would have cost the rest of the day, and the bug would have shipped
wearing documentation.

## 5. Twice, the instrument was broken and answered anyway

**The `^D` that wasn't.** Jeremy reported the banner's top line looked wrong. It did — in my
capture. `script -q /dev/null` feeds an EOF to the pty it allocates, and that byte lands at the top
of the output. The banner was fine. I'd have "fixed" a correct program if I'd trusted the capture.
Reproducing under `python3 -c "import pty; pty.spawn(...)"` showed a clean render.

**The spinner that looked frozen.** Checking the four frames cycled:

```bash
grep -oE '🐘 .\[38;5;103m.' out.txt | sort -u   # → 1 result
```

One frame. Animation broken. Except `.` in a byte-oriented match eats a single byte of a
multi-byte glyph, so every extracted string was cut mid-character. Counting each frame separately:

```
◐: 4   ◓: 3   ◑: 3   ◒: 3
```

Thirteen renders, all four frames, cycling exactly as designed.

Both times the measurement returned a plausible answer instead of an error — which is far more
dangerous than a crash, because you act on it with confidence.

## 6. Two tests that couldn't fail

Writing an SSRF guard for the new `fetch_url` tool, I had six tests asserting "no request was
made". They passed. They would also have passed with the guard deleted.

The helper returned Guzzle's history container **by value**, so the caller's array was permanently
empty. `expect($history)->toBeEmpty()` was asserting nothing, forever.

Then, testing the allowlist, I wrote this:

```php
expect(UrlGuard::inspect($url)['ok'] ?? false)
    ->toBe(UrlGuard::inspect($url)['ok'] ?? false);
```

Both sides are the same expression. It asserts that a function is deterministic.

The habit that catches both: **neuter the feature and confirm the tests go red.** Stubbing
`isPublic()` to `return true` failed eight tests. That number is the only evidence the guard is
real. A guard whose tests still pass with the guard disabled is decoration.

The same discipline caught a genuine inversion later — `messages(0)` was documented to replay
nothing and actually returned *everything*, because the `$window > 0` check had been folded into a
ternary that fell through to "return all". The caller guarded it separately, so the app behaved
correctly while the contract was exactly backwards.

## What the day actually produced

| | |
|---|---|
| Tests | 220 → **332** (1,153 assertions) |
| Commits | 12 |
| Lines of my own code deleted the same day I wrote them | ~40 |
| Bugs found by reproducing rather than reasoning | 3 |
| Broken measuring instruments | 2 |

Features shipped too — sessions that survive process exit, durable memory, a gated fetch tool that
can't be aimed at the LAN, `--yolo`, a spinning PHP elephant. Track B of the v0.2 roadmap closed.

But the through-line isn't the features. Four separate times, the thing that changed the plan was a
ninety-second check I could easily have skipped: a curl that isolated a 400, a paragraph that
wrapped visibly wrong, a `cd` into a temp directory, a stubbed function that failed eight tests.

Each one was cheaper than the work it redirected. The `.env` check alone saved a day of building
on a mechanism that was silently inert — and would have shipped *with documentation explaining how
to use it*.

The code was the easy part. Knowing whether it did anything was the job.
